# 性能检视指南（performance 维度）— code-check

## 定位

通知服务是系统高频基础服务（通知发布/删除/订阅回调在系统运行期持续发生），性能缺陷直接影响
整机流畅度与功耗。本维度检查高频路径开销、锁行为、IPC 效率、启动性能、内存与流量。

---

## 检查清单

### 1. 高频路径开销（发布/删除/订阅回调/角标更新）

- [ ] **PERF-01 频繁堆分配**：高频路径（每次通知处理必经）新增 `new`/`std::string` 构造/容器临时对象；字符串拼接用 `+` 而非 `reserve`/`append`
- [ ] **PERF-02 不必要拷贝**：`Notification` 等大对象按值传参/按值捕获 lambda；应 `const&` 传递、必要时移动
- [ ] **PERF-03 重复计算**：循环内重复查询不变量（循环内每次 `GetSlot()`，应提出循环）
- [ ] **PERF-04 高频路径日志**：正常分支打 INFO 级日志（官方 DFX-L11 禁令，与 DFX 维度重叠时合并）

### 2. 锁行为

- [ ] **PERF-05 锁内耗时操作**：持锁期间执行 IO（RDB 读写）、IPC 调用、复杂计算、睡眠等待——持锁时间直接串行化所有并发通知操作
- [ ] **PERF-06 锁粒度过大**：一个全局大锁保护多个独立容器；应按容器/分片细化
- [ ] **PERF-07 锁内回调**：持锁触发订阅者 IPC 回调——既死锁风险（LOGIC-N01）又拖长临界区；正确模式：锁内拷贝回调列表 → 锁外逐个回调

### 3. IPC 效率

- [ ] **PERF-08 循环单次 IPC**：循环内逐条调用单条接口（N 次 `GetNotification`）而非批量接口；应使用/新增批量查询
- [ ] **PERF-09 序列化开销**：大对象（像素图/长文本）不必要的跨进程拷贝次数；`WantAgent` 等冗余字段是否随全量传输
- [ ] **PERF-10 同步 IPC 可异步化**：非关键路径的同步等待（可延迟通知的结果）阻塞调用方

### 4. 启动性能

- [ ] **PERF-11 SA 启动阻塞**：`OnStart()`/`Init()` 同步 IO、等待其他 SA 就绪、同步加载大配置（与 CHK-P01 重叠时合并，性能侧重耗时影响）
- [ ] **PERF-12 按需初始化**：非首屏必需的初始化（分布式连接、大表加载）延迟到首次使用

### 5. 容器与算法

- [ ] **PERF-13 线性查找**：订阅者/通知按 key 频繁查找用 `std::vector` 遍历（O(n)），规模大时应 `unordered_map`
- [ ] **PERF-14 迭代器失效**：遍历容器中 `erase`（应 `iter = erase(iter)` 或先收集后删除）
- [ ] **PERF-15 复杂度退化**：嵌套循环处理通知列表（O(n²)，通知数量大时耗时陡增）

### 6. 内存与容量

- [ ] **PERF-16 无上限缓存**：新增缓存/列表无淘汰策略（通知历史、订阅会话）——内存持续增长
- [ ] **PERF-17 大对象生命周期**：图片/像素图持有时间过长（通知删除后仍被引用）

### 7. LiveView 实况窗（高频更新场景）

- [ ] **PERF-18 更新频率**：实况窗更新无节流/合并（应用高频 update 全量处理），按规格限频
- [ ] **PERF-19 更新最小化**：全量重建通知对象 vs 增量更新字段

### 8. 分布式同步开销

- [ ] **PERF-20 同步批量合并**：多条通知逐条跨设备发送而非批量；同步频率无控制
- [ ] **PERF-21 软总线唤醒**：非紧急同步唤醒低功耗设备（功耗敏感）；离线设备重连风暴（重连后全量补发无节奏控制）
- [ ] **PERF-22 序列化体积**：同步报文携带冗余字段（全量 notification 而对端只需元数据）

### 9. DFX 开销（与 DFX 维度重叠时归并）

- [ ] **PERF-23 打点字符串**：事件参数字符串无条件构造（即使事件被过滤）；应延迟构造
- [ ] **PERF-24 trace 粒度**：高频短操作（<1ms）加详细 trace

---

## 检测方法

1. 定位变更涉及路径是否高频：`grep` 调用方数量、判断是否在 publish/subscribe/删除主链路
2. 锁内操作：从 `lock_guard` 声明到作用域结束逐行检查
3. 循环内 IPC/分配：检查循环体
4. 无法静态判定耗时 → 标注"建议 benchmark 验证"（`test/bechmarktest/` 有基准测试框架）

## 严重等级映射

| 类别 | 默认等级 |
|---|---|
| 锁内 IO/IPC（高频路径）、O(n²) 大规模路径、无上限内存增长 | **P1**（性能类无 P0：不直接破坏正确性，但高频路径锁内 IO 在通知风暴时可致系统卡死，可上调） |
| 高频路径频繁分配、循环单次 IPC、全量同步风暴 | **P1/P2**（按频度与规模判定） |
| 线性查找、延迟初始化缺失、trace 粒度不当 | **P2** |
| 微优化建议 | **P3** |

## 输出格式

发现以 `PERF-xxx` 编号输出（见 report-template.md），每条包含：位置、问题、触发频率（该路径多频繁执行）、量级估计（n 规模/分配大小/持锁时长）、建议（含修复示例）。原始产出保存至 `.codecheck/raw/performance.md`。
