# 功能检视指南（functionality 维度）— code-check

## 定位

功能维度回答**"变更做的是不是要做的事"**——需求级正确性（逻辑维度回答"代码内部做得对不对"，两者互补）。

**与逻辑维度的边界**：
- 功能：对照需求/任务意图，检查实现完整性、行为符合性、边界场景、特性开关路径
- 逻辑：不依赖需求背景，检查控制流/数据流/状态机/边界条件/错误处理的代码级缺陷

## 输入依赖

本维度消费 SKILL.md Step 0 问题 3 收集的**需求/任务背景**：
- 有背景：逐条对照验收要点
- 无背景：以 diff 推断变更意图，对无法推断意图的行为变更标注"需开发者确认"，不得默认放行

---

## 检查清单

### 1. 需求意图对照

- [ ] **FUNC-01 实现完整性**：变更是否覆盖任务/需求的全部要点；是否有遗漏的子需求（对照需求描述或验收标准逐条勾稽）
- [ ] **FUNC-02 范围收敛**：是否实现了超出需求范围的功能（越界功能未经评审即风险）
- [ ] **FUNC-03 意图可追溯**：diff 中每处行为变更都能对应到需求条目或明确的工程理由；无法追溯的变更逐条列出

### 2. 行为符合性

- [ ] **FUNC-04 无意行为变更**：diff 中的条件修改、默认值变化、阈值调整、时序变化是否是有意为之（对照需求）：
  - `if` 条件运算符/操作数变化
  - 常量/枚举默认值变化
  - 回调触发顺序变化
  - 返回值语义变化
- [ ] **FUNC-05 部分实现**：需求要求的行为只覆盖了部分分支（如只处理了新通知、未处理更新的）

### 3. 边界场景完整性（ANS 场景矩阵）

通知服务的典型边界，逐项核对新增/修改逻辑是否处理：

| # | 场景 | 检查点 |
|---|---|---|
| 1 | 多用户 | userId 隔离正确；多用户并发订阅/发布互不串扰 |
| 2 | 勿扰模式开启 | DND 生效时通知按勿扰策略处理（静默/放行），开关切换瞬间的行为 |
| 3 | 分布式开关关闭 | `distributed_notification_service_feature_distributed_supported = false` 时相关路径不执行且不报错 |
| 4 | 角标关闭 | `..._feature_badge_manager = false` 时角标路径行为 |
| 5 | LiveView 不支持 | `..._feature_local_liveview = false` 或设备不支持实况窗时的降级（拒绝发布还是转普通通知，需符合规格） |
| 6 | Slot 不存在/被禁用 | 渠道未创建、用户关闭渠道声音/振动时的行为符合规格 |
| 7 | 通知数量上限 | 达到流控上限后的行为（拒绝+错误码+流控事件） |
| 8 | 应用未安装/已卸载 | bundleName 对应应用不存在时的查询/发布行为 |
| 9 | 息屏/后台 | 通知到达时息屏状态的展示策略（如规格涉及） |
| 10 | 空输入 | 空标题/空内容/空 bundleName 的合法处理（与安全维度输入校验重叠时合并） |

- [ ] **FUNC-06** 上表适用场景逐项核对，未处理项按规格判定是缺陷还是规格允许

### 4. 特性开关双路径（notification.gni）

变更若涉及或新增特性开关（`notification.gni` 中 `declare_args` 声明的全部特性参数，含 `distributed_notification_service_feature_*` 系列、`hisysevent_usage`、`ans_hitrace_usage`、`standby_enable` 等，以文件实际内容为准），必须验证：

- [ ] **FUNC-07 on/off 双路径可编译**：开关两种取值下代码都能编译通过（条件编译包裹完整，无悬空引用）
- [ ] **FUNC-08 on/off 双路径行为正确**：
  - 开关关闭时：功能不可用但不崩溃、不报未定义错误、相关 IPC 返回明确错误码
  - 开关打开时：功能按规格工作
- [ ] **FUNC-09 开关默认值**：新增开关默认值与产品策略一致（默认关闭的开关需说明哪些产品打开）

### 5. 业务语义正确性（对照 AGENTS.md 术语）

- [ ] **FUNC-10 Slot 渠道语义**：该类通知的声音/振动/角标/锁屏等默认提醒方式逻辑与渠道定义一致（修改 Slot 逻辑影响所有使用该渠道的通知，需全局评估）
- [ ] **FUNC-11 DND 勿扰语义**：勿扰模式下静默/重复提醒/白名单行为符合勿扰规格（`services/ans/src/disturb_manager/`）
- [ ] **FUNC-12 LiveView 语义**：实况窗通知的更新/结束/超时流程符合规格（`services/ans/src/advanced_notification_publish/live_publish_process.cpp` + `system_live_view/`）
- [ ] **FUNC-13 角标语义**：角标增/减/清零/显示规则的正确性（`services/ans/src/badge_manager/`）
- [ ] **FUNC-14 订阅语义**：订阅过滤条件（bundleName/slot/用户）生效正确，退订后不再收到回调

### 6. 分布式四场景行为（ANS 陷阱 A7 行为部分，全集定义见 [ans-pitfalls.md](ans-pitfalls.md)）

- [ ] **FUNC-15 离线**：对端设备离线时，通知本地正常，同步挂起/丢弃策略符合规格
- [ ] **FUNC-16 重连**：对端重新上线后，挂起的同步如何处理（补发/丢弃），不重复不丢失
- [ ] **FUNC-17 版本不匹配**：对端系统版本较旧/较新时，同步安全降级（协议兼容见 compatibility 维度 COMP-Z，行为正确在本维度）
- [ ] **FUNC-18 授权变更**：用户关闭对某设备的同步授权后：不再向该设备发送、已有数据处理（删除/保留）符合规格

### 7. 非预期副作用

- [ ] **FUNC-19 超范围影响**：变更影响的代码路径超出需求声明的范围（如修改公共工具函数影响其他模块行为）
- [ ] **FUNC-20 隐式依赖**：新行为依赖了未声明的环境状态（其他服务已启动、特定配置存在）

---

## 检测方法

1. `git diff` 通读全部变更，按 FUNC-01~03 勾稽需求
2. 对每个新增分支/条件，套用边界场景矩阵（第 3 节）
3. 涉及特性开关的文件：`grep -rn "feature_name" --include="*.gni" --include="*.cpp"` 确认 on/off 路径
4. 无法静态判定的行为项 → 标注"建议运行验证"，给出验证步骤（不阻塞检视结论，但计入发现）

## 严重等级映射

| 类别 | 默认等级 |
|---|---|
| 需求核心功能未实现/实现错误、特性开关 off 路径崩溃、分布式场景数据丢失 | **P0** |
| 边界场景未处理（规格要求时）、部分分支未实现、无意行为变更 | **P1** |
| 次要场景未覆盖、语义偏差不影响主流程 | **P2** |
| 建议补充的场景处理 | **P3** |

## 输出格式

发现以 `FUNC-xxx` 编号输出（见 report-template.md），每条包含：位置、问题、需求依据（引用任务描述/验收标准条目）、影响场景、建议。原始产出保存至 `.codecheck/raw/functionality.md`。
